# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  第1回（`app.ask`）では講座固有の知識を持たないため、「3レベル」について聞いても一般論で答えるか「分からない」となっていた（実際の講座の定義と乖離していた）。一方、第3回のエージェント（`app.agent`）は自律的に `search_glossary` ツールを呼び出して `data/glossary.json` の正確な定義（基礎・実装・発展）を参照し、正しく回答できるようになった。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - `[tool call] search_glossary({'query': '3レベル'})`
  - `[tool call] make_quiz({'lecture': 2})`
- 1つの質問での LLM 呼び出し回数（`requests`）：
  `requests=2`（1回目は質問内容からどのツールを呼ぶか判断する呼び出し、2回目はツールの実行結果を受け取って最終的な回答文を生成する呼び出し）。
- 追加したツールと、docstring に書いた説明：
  - 追加したツール：`make_quiz`
  - docstring：
    ```text
    講座の用語集から用語を検索し、用語に関する問いと解答を返す。

    クイズ作成依頼があったときに使うこと。
    lecture には講義回数が入る。（例：第3回）。
    ```

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  `app/agent.py` の `INSTRUCTIONS` を変更した。元の具体的なツール指定（「必ず search_glossary で用語集を確認する」「回の内容を聞かれたら get_lecture_summary を使う」）を削除し、`- 質問者の問いに対してツールを使って解答する。` というシンプルな指示に書き換えて、ツールの呼ばれ方や回答の挙動を `--trace` で比較した。
- 結果：
  個別のツール名を指示から消したにもかかわらず、「3レベルとは？」に対しては `search_glossary`、「第3回では何を学ぶ？」に対しては `get_lecture_summary` を自律的に選択して呼び出した（`requests=2`）。また、「富士山は何メートル？」という用語集に関係ない質問ではツールを呼ばずに1回（`requests=1`）で回答した。
- 気づき・疑問：
  エージェントへの指示（`INSTRUCTIONS`）に「この条件のときはこのツールを呼べ」と細かく書かなくても、各ツールの docstring（説明文）が的確に書かれていれば、モデル自身が自律的に適切なツールを判断して呼び出せることが分かった。関数の docstring が単なるコメントではなく、AI を動かすための「API仕様書」として機能していることを実感できた。
